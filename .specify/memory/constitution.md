# Конституция WorkSpace

Версия 1.0.0 · ратифицирована 2026-11-11 · применима ко всем фичам репозитория.

## Принципы

### I. Продукт — источник правды
Любой текст о программе (сайт, README, релизные заметки) описывает только то, что
действительно реализовано: сверяется с `src/`, `electron/` и `README.md`. Числа
(версия, размер архива, счётчики) берутся из реального релиза, а не придумываются.
Нельзя выдумывать метрики, отзывы, логотипы клиентов и цитаты.

### II. Никаких личных данных в публичных артефактах
Скриншоты, примеры, демо-данные и архивы релиза не содержат личных файлов, путей
пользователя, ключей, имён людей и переписки. Скриншоты снимаются на чистом
профиле приложения (`--user-data-dir` во временной папке) поверх синтетической
демо-папки, которая генерируется скриптом. Секреты (`API_KEY`, `secrets.local.ps1`,
`*.local.ps1`) не попадают ни в один публичный артефакт; проверка выполняется
перед публикацией.

### III. Статика без сборочного шага
Сайт — обычные файлы (`docs/index.html`, `docs/styles.css`, `docs/assets/**`),
которые открываются как есть и публикуются GitHub Pages из подпути
`https://<owner>.github.io/<repo>/`. Только относительные пути (`assets/...`,
`styles.css`), без абсолютных `/`, без серверного кода, без runtime-зависимостей
и внешних CDN: страница работает без сети, кроме самих ссылок на релизы.

### IV. Дизайн по Hallmark, без «AI-шаблона»
Вёрстка следует Hallmark v2.0.0: все цвета и шрифты — через токены `:root`;
`overflow-x: clip` на `html` и `body`; `:focus-visible` у каждого интерактивного
элемента; анимации только `transform`/`opacity` и с `prefers-reduced-motion`;
никаких выдуманных метрик, «eyebrow»-подписей, средних точек в мета-строках и
эмодзи-иконок. Проверка — `sloplint.mjs --render` без `FAIL`.

### V. Доступность и адаптивность — часть готовности
Контраст текста не ниже 4.5:1, осмысленная иерархия заголовков, `alt` у
скриншотов, клавиатурная навигация, раскладка 390 / 768 / 1280 / 1920 px.
Первый экран содержит заголовок, одно предложение и основное действие целиком
при 1280×800. Контент читается при отключённом JavaScript.

### VI. Воспроизводимость артефактов
Скриншоты и демо-данные не рисуются руками: их создают скрипты из
`scripts/site/` (генерация демо-папки, запуск приложения, съёмка кадров), поэтому
кадры обновляются одной командой после изменения UI.

## Ограничения и процесс

- Сборка и проверки: `npm run build`, `npm run typecheck` — должны проходить.
- Правки существующего кода приложения — только если без них фича не работает.
- Публикация: ветка `main`, артефакт Pages — каталог `docs/`, `.nojekyll` обязателен.
- Коммиты — Conventional Commits, одна причина на коммит.

## Управление

Изменения конституции фиксируются здесь с указанием версии и причины; любая
спецификация проходит Constitution Check и не может нарушать Принципы II и III.
