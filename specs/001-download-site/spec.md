# Feature Specification: Сайт скачивания WorkSpace

**Feature Branch**: `001-download-site`

**Created**: 2026-11-11

**Status**: Implemented

**Input**: «Сделай удобный сайт для скачивания нашей программы, а также его описание
со скриншотами. На скриншотах не должно быть личных файлов. Сайт должен работать
на GitHub Pages.»

## Контекст

WorkSpace — portable-приложение для Windows x64 (Electron), один релизный архив
`WorkSpace-<version>-win-x64.zip` в GitHub Releases. Сайта у продукта нет: страница
README на GitHub и есть «лендинг». Нужна страница, на которую можно дать ссылку
человеку, не знакомому с репозиторием: что это, что умеет, как выглядит, где
скачать.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Скачать программу за один шаг (Priority: P1)

Человек открывает страницу с телефона или ноутбука, за первый экран видит, что
это за программа и для какой ОС, и нажимает «Скачать для Windows». Он попадает
сразу на файл последнего релиза, а не на список обсуждений.

**Why this priority**: без понятного скачивания страница не выполняет работу.

**Independent Test**: открыть страницу на 1280×800, найти основное действие без
прокрутки, проверить, что ссылка ведёт на существующий ассет последнего релиза.

**Acceptance Scenarios**:

1. **Given** страница загружена при 1280×800, **When** смотрю первый экран,
   **Then** заголовок, одно предложение и кнопка скачивания видны целиком.
2. **Given** нажата основная кнопка, **When** открывается ссылка,
   **Then** это `releases/download/v<version>/WorkSpace-<version>-win-x64.zip`
   существующего релиза, и рядом указаны версия и размер архива.
3. **Given** нужен другой канал, **When** нажимаю вторичную ссылку,
   **Then** открывается страница релизов, где лежат все версии.

### User Story 2 — Понять, что умеет программа (Priority: P2)

Человек читает разделы о возможностях и решает, подходит ли ему инструмент: какие
форматы открываются, что делает AI-ассистент, нужен ли Microsoft Office, что с
приватностью ключей.

**Why this priority**: описание снимает главный вопрос — «зачем мне это вместо
Word/Excel».

**Independent Test**: прочитать страницу сверху вниз и ответить на вопросы:
форматы, офлайн, ключи, ОС, требования.

**Acceptance Scenarios**:

1. **Given** страница открыта, **When** пролистываю разделы,
   **Then** вижу список форматов, возможности AI (BYOK), кодировки, обновления,
   горячие клавиши, ограничения.
2. **Given** я не читаю README репозитория, **When** смотрю страницу,
   **Then** все утверждения совпадают с реализованным поведением программы.

### User Story 3 — Увидеть интерфейс до установки (Priority: P2)

Человек смотрит на реальные кадры приложения: Word, Excel, Markdown, код,
презентации, AI-чат. На кадрах нет ни одного личного файла — только
демонстрационные документы.

**Why this priority**: для настольного приложения скриншот убеждает сильнее текста.

**Independent Test**: открыть каждый скриншот и убедиться, что в нём нет имён
пользователя, личных путей, переписки и секретов.

**Acceptance Scenarios**:

1. **Given** страница открыта, **When** навожу на скриншот,
   **Then** вижу подпись, объясняющую, что на нём показано.
2. **Given** скриншот открыт в полном размере, **When** разглядываю содержимое,
   **Then** все файлы в дереве и все тексты — синтетические.
3. **Given** UI изменился, **When** я запускаю скрипт съёмки,
   **Then** кадры пересоздаются без ручной работы.

### User Story 4 — Открыть страницу с телефона или на медленном канале (Priority: P3)

Страница читается на 390 px, не имеет горизонтальной прокрутки, картинки не
грузятся все сразу, при отключённом JavaScript контент остаётся видимым.

**Why this priority**: ссылку пересылают в мессенджерах, смотрят с телефона.

**Independent Test**: эмуляция 390×844, отключённый JS, throttle сети.

**Acceptance Scenarios**:

1. **Given** ширина 390 px, **When** листаю страницу,
   **Then** нет горизонтального скролла и обрезанного текста.
2. **Given** JavaScript отключён, **When** открываю страницу,
   **Then** весь текст и скриншоты на месте.
3. **Given** включён `prefers-reduced-motion: reduce`, **When** открываю страницу,
   **Then** анимаций нет, контент виден.

### Edge Cases

- Страница опубликована из подпути `https://disemay12.github.io/workspace/`:
  все локальные пути обязаны быть относительными, иначе стили и кадры отдают 404.
- Jekyll на GitHub Pages игнорирует каталоги с `_`: нужен `.nojekyll`.
- Релиз новее версии, записанной на странице: страница не должна обещать
  несуществующий файл — основная кнопка ведёт на `releases/latest`, а точная
  ссылка на версию помечена как «проверенная».
- Пользователь открыл `index.html` локально (file://): относительные пути
  работают, внешние шрифты и CDN отсутствуют.
- Ширина 1920 px: контейнер ограничен, поля растут, строки не растягиваются.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Страница MUST быть набором статических файлов в `docs/`, без
  сборочного шага и серверного кода.
- **FR-002**: Все локальные ссылки MUST быть относительными, чтобы страница
  работала из подпути GitHub Pages и из `file://`.
- **FR-003**: Первый экран MUST содержать название, одно предложение о продукте и
  основное действие в пределах 1280×800.
- **FR-004**: Основное действие MUST вести на ассет последнего релиза; вторичное —
  на список релизов; рядом MUST быть указаны версия и размер архива.
- **FR-005**: Страница MUST описывать: назначение, форматы и редакторы, AI-режим
  BYOK, кодировки, обновления, горячие клавиши, требования, ограничения.
- **FR-006**: Страница MUST показывать не менее 5 скриншотов реального интерфейса
  с подписями и `alt`-текстом.
- **FR-007**: Скриншоты MUST быть получены с чистого профиля приложения и
  синтетической демо-папки; ни один кадр не содержит личных файлов, путей и ключей.
- **FR-008**: MUST существовать скрипт, пересоздающий демо-данные и скриншоты
  одной командой.
- **FR-009**: Страница MUST иметь корректные `title`, `description`, Open Graph,
  `lang="ru"`, favicon, и не делать внешних запросов.
- **FR-010**: Контент MUST читаться при отключённом JavaScript; анимации MUST
  уважать `prefers-reduced-motion`.
- **FR-011**: Страница MUST быть пригодной для публикации: `.nojekyll`, workflow
  GitHub Pages, инструкция включения.
- **FR-012**: Страница MUST NOT содержать выдуманных метрик, отзывов, логотипов и
  цитат.

### Key Entities

- **Релиз**: `tag`, `version`, `assetName`, `assetSize`, `downloadUrl`, `pageUrl`.
- **Скриншот**: файл в `docs/assets/screens/`, подпись, `alt`, размеры, экран
  приложения и сценарий съёмки.
- **Раздел описания**: заголовок, текст, иллюстрация, источник факта в репозитории.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Кнопка скачивания и заголовок видны без прокрутки на 1280×800 и на
  390×844 (проверяется скриншотом страницы).
- **SC-002**: Ноль 404 по локальным ресурсам при открытии из подпути `/workspace/`
  и из `file://`.
- **SC-003**: Ноль личных данных на кадрах: проверка списка файлов демо-папки и
  визуальный осмотр каждого кадра.
- **SC-004**: `sloplint.mjs --render` — 0 `FAIL`; Lighthouse (mobile) — Performance
  ≥ 90, Accessibility ≥ 95.
- **SC-005**: Пересоздание скриншотов и страницы — одна команда, без ручных правок.
- **SC-006**: Все утверждения страницы проверяемы по `src/`, `electron/`,
  `README.md`; вымышленных чисел нет.

## Assumptions

- Целевая ОС продукта — Windows x64; мобильная версия страницы нужна только для
  чтения, кнопка скачивания ведёт на Windows-архив.
- Репозиторий публичный, GitHub Pages доступен из подпути проекта.
- Домен и аналитика не требуются; внешние CDN и шрифты не используются.
- Демо-документы генерируются локально (python-docx, openpyxl, python-pptx) и не
  коммитятся в репозиторий.
