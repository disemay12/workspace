# Last_Plan — полноценное управление документами через AI-ассистента

## Цель

Сделать WorkSpace IDE-подобной средой для работы с документами: AI-ассистент должен уметь читать, искать, точечно править, перестраивать, форматировать, сохранять и откатывать изменения во всех поддерживаемых типах файлов. Основной приоритет — Word и сохранность `.docx`; Excel, PowerPoint и Markdown подключаются после Word-ядра.

## Принятые решения

1. **Типы файлов:** Word, Markdown, Excel, PowerPoint. Для PowerPoint нужен полноценный редактор, сейчас есть только просмотрщик.
2. **Word fidelity:** near-Word. Каноническим представлением Word является OOXML-пакет, а не HTML. Неподдерживаемые сложные объекты (SmartArt, диаграммы, content controls, сложные поля) сохраняются без потерь и остаются read-only, если для них нет явной поддержки.
3. **Редактор:** остаёмся на contenteditable. HTML — представление; команды и транзакции работают через модель документа.
4. **Применение правок AI:** автоматическое, без подтверждения. Каждый ответ — атомарная транзакция с diff, подсветкой изменений, историей и откатом.
5. **Multi-document:** по умолчанию активный документ. Дополнительные файлы подключаются явно; по умолчанию только чтение, запись — после явного разрешения.
6. **Порядок:** сначала Word-ядро и fidelity, затем Excel/PowerPoint/Markdown-углубление и IDE-обвязка.

## Правила ведения плана

- Статусы:
  - `[ ]` — не начато;
  - `[~]` — в работе;
  - `[x]` — выполнено и проверено;
  - `[!]` — заблокировано, с причиной.
- Шаг помечается `[x]` только если он **реально работает** и проверен.
- Для каждого шага фиксируется проверка: команда, результат, при необходимости — ручной сценарий.
- Нельзя помечать шаг выполненным по факту написания кода. Нужен зелёный typecheck/build и соответствующий тест или ручная проверка.
- После каждого этапа обновляется раздел «Журнал проверок».
- Не ломать существующие сценарии: `doc-agent-check`, `insert-check`, `docx-check` (после починки), новые проверки.

## Критерии готовности всего проекта

1. AI выполняет точечные операции без полной замены документа.
2. Любая правка AI атомарна, видна в истории и откатывается.
3. Выделение и диапазоны реально используются инструментами.
4. Word round-trip сохраняет headers/footers, TOC, сноски, комментарии, секции и сложные объекты (read-only preservation).
5. Excel и PowerPoint редактируются через AI и сохраняются.
6. Multi-doc: дополнительные файлы read-only без разрешения.
7. Нет регрессий существующих сценариев; все проверки зелёные.
8. Для каждого пункта есть проверка: unit/e2e или ручной сценарий.

## Риски

- **OOXML fidelity:** самый большой риск; нужен корпус реальных файлов и golden-тесты.
- **contenteditable ↔ модель:** потеря каретки, форматирования и порядка runs; нужен строгий маппинг и тесты.
- **Полный PowerPoint-редактор:** фактически новый продукт внутри продукта.
- **Производительность:** полная пересборка HTML/пакета на каждую правку недопустима.
- **Сложные объекты Word:** preservation и редактирование — разные уровни; не обещать редактирование того, что сохраняется read-only.
